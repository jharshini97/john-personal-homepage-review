# Project 1 Design Document

## Project Title

**The Personal Index**

---

## Project Description

The Personal Index is a personal homepage designed to present a well-rounded picture of who I am beyond a traditional résumé or professional portfolio.

The site will introduce visitors to my background, interests, education, professional experience, current transition into information technology and computer science, and selected technical projects.

The design will use a minimal and modern visual style built around typography, spacing, content cards, subtle borders, and interactive elements rather than relying heavily on personal photography.

The website will be implemented as a front-end-only static site using:

- Vanilla HTML5
- CSS3
- ES6+ JavaScript
- ES6 modules

The project will not use:

- A backend
- jQuery
- Bootstrap
- Component libraries

The primary goal is to create a homepage that feels personal, informative, visually engaging, and easy to navigate while remaining clean and modern.

---

# Concept

The website will function as a **personal index**.

Rather than presenting information as a chronological timeline, the homepage will organize different areas of my life into clear categories that visitors can explore independently.

These categories will include:

- Background
- Interests
- Current activities
- Education
- Professional experience
- Technology
- Projects

This structure allows visitors to quickly understand different aspects of who I am without requiring them to follow a fixed sequence.

---

# Design Goals

The website should:

- Feel minimal and modern
- Be visually engaging without feeling cluttered
- Provide enough meaningful content so the page does not feel empty
- Present both personal and professional information
- Make GitHub projects easy to locate
- Avoid a traditional résumé-style layout
- Avoid a chronological timeline design
- Be easy to navigate
- Clearly communicate where the visitor is on the page
- Work well on desktop, tablet, and mobile devices
- Use visual hierarchy to make content easy to scan
- Include meaningful original interaction using JavaScript
- Remain maintainable so content can be updated later
- Follow accessibility and usability best practices

# User Interface and User Experience Strategy

The website will prioritize usability and clarity.

## Navigation

The site will use a clear navigation bar containing links such as:

- About
- Interests
- Currently
- Work + Technology
- Projects

The navigation will:

- Remain visually consistent
- Use descriptive labels
- Clearly indicate interactive elements
- Support keyboard navigation
- Adapt appropriately for smaller screens

A mobile navigation pattern will be designed so links remain easy to access without overcrowding the screen.

---

## Page Orientation

Each major section will have:

- A clear section heading
- Consistent spacing
- A short introduction when necessary
- Visually distinct content blocks

Visitors should be able to understand the page structure simply by scanning the headings.

---

## Visual Hierarchy

Content importance will be communicated using:

- Heading size
- Font weight
- Spacing
- Card size
- Position
- Subtle accent colors

Important content such as the introduction and projects will receive greater visual emphasis than supporting details.

---

## Readability

The design will prioritize:

- Comfortable line lengths
- Clear font sizes
- Strong text contrast
- Consistent spacing
- Short paragraphs
- Scannable lists
- Descriptive labels

Long walls of text will be avoided.

---

## Interaction Feedback

Interactive controls will include visible:

- Hover states
- Focus states
- Active states

Buttons and links should clearly look interactive.

Important actions will use standard HTML elements such as:

```html
<button>Explore</button>
```

rather than using non-semantic elements such as `<div>` or `<span>` as buttons.

## Bento-Style Content Grid

One of the primary visual patterns will be a responsive **bento-style grid**.

Different cards may use different widths while remaining aligned to a consistent grid.

For example:

```text
┌───────────────────────────────┬───────────────┐
│ About Me                      │ Currently     │
│                               │               │
│ Background and introduction   │ Reading       │
│                               │ Watching      │
│                               │ Learning      │
└───────────────────────────────┴───────────────┘

┌───────────────┬───────────────┬───────────────┐
│ Running       │ Music         │ Reading       │
└───────────────┴───────────────┴───────────────┘

┌───────────────────────┬───────────────────────┐
│ Work + Controls       │ Technology            │
└───────────────────────┴───────────────────────┘
```

This approach will help the website feel visually rich without requiring large numbers of images.

On smaller screens, the grid will collapse into a single-column layout.

# Creative Addition

## Explore My Index

The main creative feature will be an interactive content-filtering system called **Explore My Index**.

Visitors will be able to choose categories such as:

- Everything
- Personal
- Culture
- Technology
- Career
- Media

Selecting a category will dynamically filter or emphasize related cards.

For example:

### Media

May reveal or emphasize:

- Music
- Books
- Movies
- Television

### Technology

May reveal or emphasize:

- Education
- Coding
- GitHub
- Projects

### Personal

May reveal or emphasize:

- Background
- Running
- Interests

The feature will be implemented using original ES6+ JavaScript.

Content elements will use data attributes such as:

```html
<article class="index-card" data-category="personal">...</article>
```

JavaScript will determine which items should be visible based on the selected category.

# Responsive Design

The website will be designed using a mobile-first approach.

## Large Screens

Large screens may display:

- Multi-column hero content
- Two-column About section
- Multi-column interest grid
- Side-by-side Work + Technology cards
- Multiple project cards per row

## Medium Screens

Layouts will reduce the number of columns while maintaining spacing and readability.

## Small Screens

Content will primarily display in a single column.

Navigation, cards, text, and buttons will remain easy to use on smaller screens.

---

# Accessibility Goals

The website will:

- Use semantic HTML5 elements
- Include alt text for every meaningful image
- Provide keyboard-accessible navigation
- Provide visible keyboard focus indicators
- Maintain readable color contrast
- Use descriptive link text
- Use real `<button>` elements for actions
- Avoid using color alone to communicate information
- Maintain readable text sizes
- Use an appropriate heading hierarchy
- Support responsive layouts
- Include a skip-to-content link where appropriate
